# 08 — Датасет і LoRA-адаптер для Mistral, навченого на корпусі статей

**Дата**: 2026-10-02 · **Замінює** `CODE_REVIEW_v1/10_TRAINING_DATASET_PLAN.md` (2026-06-11): обсяги перераховано повним проходом по файлах, а не з документів.

**Ціль**: ≥ 10 000 прикладів. План — 60–80 тис. SFT-прикладів + 10–15 тис. пар переваги, з негативними прикладами в кожному сімействі.

---

## 1. Що LoRA вміє і чого не вміє (чесна межа)

| LoRA **дає** | LoRA **не дає** |
|---|---|
| дисципліну формату: JSON-екстракція за схемою, ключі онтології, одиниці, `suspect` | надійні **факти** про конкретні статті: числа й цитати лишаються в індексі (RAG), а не у вагах |
| мову домену: SAR, HAND, NSE/KGE, DEM, гідравлічні моделі, плутанина акронімів | знання про статті, яких не було в датасеті |
| поведінку: цитувати лише надані докази, **відмовлятися**, коли доказу немає, не посилювати твердження | гарантію коректності: потрібні оцінка й ворота |
| дешевий локальний **замінник Gemini** для скринінгу, екстракції й попередньої перевірки тверджень: без квоти 480 запитів на день на лейн, без відправки текстів назовні, з версією адаптера в provenance | |

Тому датасет навчає **навичок над наданим контекстом** (сімейства A–M нижче).
Безперервне донавчання на сирому тексті (K) — окремий опційний експеримент, не основа.

**Куди адаптер підключається в API** ([03](03_API_DESIGN.md), [04 §6](04_ARCHITECTURE.md)): провайдер `ollama:geohydro-nemo:v1` у LLM-шлюзі з маршрутизацією за задачами:
- `/discovery/screen`;
- `/metrics/extract?mode=llm`;
- попередній фільтр `/claims/check`;
- `/ontology/normalize` для неоднозначних випадків.

## 3. Варіанти датасету (сімейства задач)

Позначки джерела міток:
- **DET** — детерміновані (рядкові перевірки, онтологія, діапазони);
- **SIL** — сріблі з пайплайну, лише після DET-фільтра;
- **TCH** — вчитель (LLM) + DET-перевірка;
- **HUM** — людина.

## 4. Негативні приклади: таксономія і рецепти

| Код | Що вчить | Як генерується | Мітка | Сімейства |
|---|---|---|---|---|
| N1 | відмова, коли доказу немає | замінити контекст на тематично близькі уривки інших статей (SPECTER2-сусіди) | «У наданих джерелах немає…» + що саме відсутнє | E |
| N2 | частковий доказ | контекст має суміжний факт (калібрування замість валідації, інший басейн) | `PARTIAL` + що підтверджено, а що ні | E, F |
| N3 | **не вигадувати метрику** | абзац з «high accuracy», «good agreement» без чисел; «flood mapping» без OA (правило пам'яті *no metric fabrication*) | `metrics: []` | D |
| N4 | діапазони | синтетичні й реальні порушення: NSE > 1, kappa < −1, OA > 100 %, p > 1 (164 реальні) | `range_verdict: suspect` + причина | D |
| N5 | роль «використано» ≠ «процитовано» | речення з related work/вступу з маркером `bibr` («X et al. used Sentinel-1») | сутність з `role: cited` або відсутня в `used` | A |
| N6 | неоднозначні аліаси | 61 неоднозначний рядок, 11 колізій акронімів, підрядкові артефакти | правильний `canonical_id` або `NIL` | A, B |
| N7 | посилення / спотворення твердження | пертурбації правдивої пари: число, одиниця, напрям, хедж, масштаб, сутність, заперечення | `CONTRADICTED` / `OVERSTATED` | F |
| N8 | вторинне цитування | речення-джерело містить `bibr` на третю роботу (як Iqbal 2023 → Hawker 2022) | `PARTIAL` + «перевірте першоджерело» | F, G |
| N9 | цитата майже збігається | заміна синонімів, обрізання, склеювання двох речень, цитата з іншої статті | `NOT_FOUND` / `FUZZY` | G |
| N10 | жорсткі нерелевантні | сусіди SPECTER2 тієї ж теми з іншим твердженням; 813 NOT_RELEVANT від Gemini | `NOT_RELEVANT` | H |
| N11 | синтез без опори | у правильний абзац J вставлено факт поза доказом / неправильний `[doi]` / неіснуючий DOI | у DPO — `rejected` | J, E |
| N12 | позадоменне | питання з медицини, фінансів тощо (≤ 2 %) | «поза межами бази знань» | E |

**Пропорції**: 25–35 % негативів у кожному SFT-сімействі (не більше 40 %, інакше модель перевчиться відмовлятися). Плюс окремий набір переваги (§5), де кожен приклад містить негатив.

## 6. Вчитель і квоти

- **Gemini** (`3.1-flash-lite` / `3.5-flash-lite`): ≈ 480 запитів на день на лейн, 2 лейни ≈ 960 запитів на день. **Пакетувати 10–20 прикладів в один запит** (структурований JSON-масив) → 10–19 тис. міток на день. DS-2 (≈ 42 тис.) — це 3–5 днів квоти.
- **Локальні вчителі без квоти**:
  - `mistral-nemo:12b` (вже в Ollama);
  - `Qwen2.5-7B-Instruct` (уже в HF-кеші, Apache-2.0).
  - Слабші, тому їхні мітки приймаються лише після DET-перевірки й вибіркового контролю.
- **Умови провайдерів**: перед використанням відповідей Gemini чи Claude як міток для навчання власної моделі перевірити умови використання відповідного API. Детерміновані мітки й локальні вчителі цього питання не мають.
- **Кожна TCH-мітка зберігає**: модель, `prompt_sha256`, сиру відповідь, результат DET-перевірки. Це той самий формат, що вже використовують `screen_raw.*.jsonl`.

## 7. Формат прикладу

Розширено схему з `CODE_REVIEW_v1/10` (поля `evidence[]` і `license_tier` обов'язкові).

```json
{
  "id": "D-000421",
  "family": "D",
  "variant": "negative.N4",
  "messages": [
    {"role": "system", "content": "Extract evaluation metrics as JSON. Use only numbers present in the input. Flag values outside the valid range."},
    {"role": "user", "content": "<table caption + markdown rows from TEI>"},
    {"role": "assistant", "content": "{\"metrics\":[{\"metric\":\"metric.nse\",\"value\":1.3,\"unit\":null,\"range_verdict\":\"suspect\",\"reason\":\"NSE must be <= 1\",\"evidence\":\"NSE 1.30\"}]}"}
  ],
  "evidence": [{"paper_key": "doi:10.xxxx/yyyy", "source": "tei_table", "locator": "tab_3/r5c2"}],
  "labels": {"source": "DET", "checks": ["value_in_input", "range_rule"], "teacher": null},
  "license_tier": "abstract_only",
  "split": "train",
  "split_key": "doi:10.xxxx/yyyy",
  "dataset_version": "ds1-v1",
  "provenance": {"git_commit": "…", "kb_version": "…", "built_at": "2026-…"}
}
```

- **Шаблон чату** — Mistral-NeMo: системне повідомлення додається до першого `[INST]`. Застосовувати через `tokenizer.apply_chat_template`.
- **Втрата** рахується **лише на відповіді асистента**.
- **Довжина**: ≤ 2 048 токенів для A, B, C, D, G, L, M; ≤ 4 096 для E, F, H, I, J (з контекстами).

## 8. Оцінка і ворота прийняття адаптера

| Що міряємо | Набір | Поріг прийняття v1 |
|---|---|---|
| Екстракція (A, B, D, L): F1 за полями, точний збіг `canonical_id`, значення й одиниці | held-out + gold | F1 ≥ база + 10 п.п.; **частка вигаданих чисел ≤ 0,5 %** (значення немає у вході) |
| Діапазони (D, N4) | синтетичні + 164 реальні | `suspect`-recall ≥ 95 % |
| Відмова (E, N1) | unanswerable-набір | recall відмови ≥ 90 %, хибні відмови ≤ 10 % |
| Перевірка тверджень (F) | held-out + **фікстури 2026-10-01** | macro-F1 ≥ база + 10 п.п.; Lehnigk → `CONTRADICTED`, Zheng → `OVERSTATED`, Iqbal → вторинне, Johnson/Olofsson/Bates → `SUPPORTED` |
| Скринінг (H) | людський gold set (§8; зараз людських міток немає) + позитивні контролі звіту `kakhovka-report:v1` | recall контролів ≥ 90 % при точності не гіршій за Gemini flash-lite |
| Загальні здібності | 200 загальних інструкцій | без деградації > 5 % (контроль катастрофічного забування) |

**Порівняння**:
- база `Mistral-NeMo` (zero/few-shot);

## 10. Навчання

| Параметр | Значення | Чому |
|---|---|---|
| Базова модель | **Mistral-NeMo-12B-Instruct-2407** (Apache-2.0) | та сама родина, що `mistral-nemo:12b` у пайплайні (judge), тож заміна без зміни промптів; контекст 128k |
| Запасний варіант | Mistral-7B-Instruct-v0.3 (Apache-2.0) | ≈ 2× швидше; якщо пілот покаже, що 12B не вкладається в час |
| Ваги | HF safetensors (`mistralai/Mistral-Nemo-Instruct-2407`, ≈ 24 GB bf16) або передквантизовані 4-bit (`unsloth/Mistral-Nemo-Instruct-2407-bnb-4bit`) | GGUF з Ollama (7,1 GB) **непридатний** для навчання |
| Метод | QLoRA: 4-bit NF4, `r=16` (v1) / `32` (v2), `α=2r`, dropout 0.05, усі лінійні шари (q, k, v, o, gate, up, down) | A4000 16 GB |
| Оптимізація | lr 2e-4, cosine, warmup 3 %, 1–2 епохи, batch 1 × grad-accum 16, gradient checkpointing, bf16; DPO: β 0.1, lr 5e-6, 1 епоха | стандартні стартові значення; уточнити на пілоті |
| Середовище | **окреме** `.venv-train` (Unsloth або TRL + PEFT + bitsandbytes + datasets) | основне `.venv` закріплене на `transformers 5.8.1` заради Nougat; ця версія вже раз ламала пайплайн |
| Пілот | 1 000 прикладів, 1 епоха: заміряти токени за секунду, VRAM, якість на 200 прикладах | перш ніж запускати повний прогін |
| Оцінка часу | DS-1 ≈ 44 тис. × ~600 токенів ≈ 26 млн токенів на епоху. При орієнтовних ~400–600 ток/с для QLoRA 12B на A4000 — **≈ 12–18 год на епоху**. 7B ≈ удвічі швидше. DS-1 + DS-2 ≈ 90 млн токенів → 2–3 доби на епоху (12B) | якщо задовго — орендований A100/H100 лише на фінальні прогони, або 7B |

**Розгортання**:
1. Злиття LoRA з базою (bf16).
2. Конвертація в GGUF (`llama.cpp`) з квантизацією Q5_K_M.
3. Ollama `Modelfile`: `FROM ./geohydro-nemo-v1.Q5_K_M.gguf`, шаблон `mistral-nemo`, `PARAMETER temperature 0`.
4. Модель `geohydro-nemo:v1`.

Альтернатива — `ADAPTER` у Modelfile поверх базової моделі; підтримку для NeMo перевірити окремо.

**Тіньовий режим перед перемиканням**: 2 тижні LLM-шлюз шле ті самі запити і в Gemini, і в адаптер та логує розбіжності. Перемикання лише за воротами з §8. У provenance кожної відповіді: `adapter=geohydro-nemo:v1`, `dataset=ds1-v1@sha256`.
