## Резюме керівника

Stage 1 (pipeline_runner) завершив повний запуск корпусу: **3 546 паперів оброблено за 18 годин 7 хвилин** (середнє 18.4 с/папір, 3 воркери). Це найбільший одиничний запуск пайплайну — зростання з 145 → 3 546 файлів paper_json.

Однак сталися дві **критичні тихі помилки**, невидимі у зведенні запуску:

1. **Невідповідність розмірності ембедингів ChromaDB** — `Collection expecting embedding with dimension of 384, got 768` — логується як некритична для кожного паперу. Всі 3 546 нових паперів не пройшли векторну індексацію. Семантичний пошук зламано для нового корпусу.
2. **Нормалізація не запускалась** — 3 546 файлів paper.json існують, але `normalization_runner` не виконувався. Нормалізовані ребра сутностей відсутні для 97 % корпусу.

Оцінка довіри регресує з 6.8 → **5.9 / 10** попри повне покриття корпусу.

## 3. Аналіз команди: змінні середовища

Пайплайн запущено командою:
```bash
TOKENIZERS_PARALLELISM=false \
RAYON_NUM_THREADS=1 \
OMP_NUM_THREADS=2 \
OLLAMA_MODEL=mistral-nemo:12b \
OLLAMA_URL=http://localhost:11434 \
SPACY_MODEL=en_core_web_sm \
.venv/bin/python3 -m src.orchestration.pipeline_runner --workers 3
```

| Змінна | Значення | Призначення |
|--------|---------|-------------|
| `TOKENIZERS_PARALLELISM` | `false` | Запобігає deadlock токенізатора HuggingFace при fork Ray-воркерів. Без цього будь-яка токенізація в Ray remote function зависне безкінечно. **Обов'язково.** |
| `RAYON_NUM_THREADS` | `1` | Обмежує пул потоків Rust Rayon, що використовується Arrow/DataFusion. При 3 воркерах необмежений Rayon породжує 3×N потоків, що конкурують за CPU. Значення 1 усуває цю конкуренцію. **Виправлення стабільності.** |
| `OMP_NUM_THREADS` | `2` | Обмежує потоки OpenMP (NumPy, SciPy BLAS, внутрішні операції SpaCy). При 3 воркерах × необмежений OpenMP = перевантаження CPU. 2 — хороший баланс для 3 воркерів. |
| `OLLAMA_MODEL` | `mistral-nemo:12b` | 12B-параметрний варіант Mistral для судді LLM. Хороший баланс якості/швидкості: ~12 с затримки у вибірках. Більші моделі (70B) були б ~у 4 рази повільніші. |
| `OLLAMA_URL` | `http://localhost:11434` | Локальний ендпоінт Ollama. Тримає inference на машині, без витрат API. |
| `SPACY_MODEL` | `en_core_web_sm` | Легка модель SpaCy NER (80 МБ). Достатня точність для пайплайну сутностей. Використання `en_core_web_lg` (830 МБ) покращить NER, але потроїть RAM на SpacyActor. |
| `--workers 3` | 3 | Паралельні слоти Ray. SpacyActor (~300 МБ) + EmbeddingActor (~600 МБ) + OllamaActor + 3×500 МБ воркер-процеси ≈ **~3 ГБ RAM**. |

**18 годин 7 хвилин** для 3 547 паперів = **18.4 с/папір в середньому**. При 3 воркерах це ~6.1 с обчислень на папір у критичному шляху. Вузьке місце — OllamaActor (~12 с послідовно).
